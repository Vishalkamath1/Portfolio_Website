1. Executive Summary & Health Scorecard

A full architectural review was performed across the component hierarchy, state contexts, API endpoints, Supabase data access layer, and UI responsiveness layers.

The application demonstrates strong visual polish, solid TypeScript coverage (zero type errors on build), and resilient offline fallbacks (localStorage + mock domain data). However, several iterations of feature evolution (specifically migrating from a modal-based chat experience to an inline tripartite console in Section 5) have left behind dead components, orphaned state, redundant data fetching, and divergent API routes.

2. Component Structure & Modularity

2.1 Critical Dead Code: SarangChatModal.tsx (471 Lines)

File: src/components/SarangChatModal.tsx • Status: Completely Orphaned

Following the Section 5 upgrade to an integrated inline console, the popup modal was retired. However, the file remains in the repository. It is never imported, referenced, or rendered by any page or layout.

Impact: Increases repository clutter and cognitive overhead for future maintainers.

2.2 Zombie State & Vestigial Modal Methods in AgentChatContext.tsx

File: src/context/AgentChatContext.tsx

The context continues to expose state variables designed solely for the retired popup modal:

  • isChatOpen / setIsChatOpen
  • closeChat
  • Redundant alias exports: handleAgentSelection: openSpecialistChat, openSarangChat: openSpecialistChat
  • src/components/Navbar.tsx destructures isChatOpen without using it.

Impact: React re-render overhead when unused state variables update; cluttered context API.

2.3 Duplicate State & Redundant Supabase DB Fetch in AgentSection.tsx

File: src/components/sections/AgentSection.tsx

  • Both ProjectsSection.tsx and AgentSection.tsx invoke fetchProjectsFromDb() independently on initial mount.
  • In AgentSection.tsx, the fetched projects array is only used to compute jnanaProjects.
  • jnanaProjects is never rendered or referenced anywhere in AgentSection.tsx.
  • selectedProject is declared (useState<Project | null>(null)), passed to <ProjectModal />, but never set to any project inside Section 5.

Impact: Redundant network roundtrips to Supabase on home page load, unneeded React reconciliation cycles, and dead component mounting.

3. Supabase & API Efficiency

3.1 Route Divergence: Unused /api/chat vs Active /api/jnana

Files: src/app/api/chat/route.ts (152 lines) & src/app/api/jnana/route.ts (93 lines)

AgentSection.tsx submits messages directly to /api/jnana (fetch('/api/jnana')). /api/chat is never called by any component in the codebase.

The Problem: /api/chat contains the comprehensive, 60-line underwriting persona prompt (OWNER BACKGROUND, PORTFOLIO PROJECTS CONTEXT, SPECIALIST MODE prompts, REGULATORY GUARDRAIL, and high-fidelity fallback). Conversely, /api/jnana streams tokens using a generic system instruction: 

systemInstruction: 'You are a helpful AI assistant.'

Impact: Live Gemini responses streamed through Section 5 lack the specialized underwriting persona, ICR rules, and compliance disclaimers present in /api/chat.

Architectural Fix: Merge the rich domain prompt from /api/chat into /api/jnana's streaming pipeline, and safely retire /api/chat.

3.2 Direct Client Supabase Calls vs API Route Inconsistency

File: src/lib/supabaseClient.ts

  • Contact Form: Submits to a Next.js server route (/api/contact), performing server-side validation before writing to Supabase.
  • Reviews Form: Directly calls saveSarangReview() client-side, running supabase.from('sarang_reviews').insert(...) using the public anon key from the browser.
  • Projects CMS: Directly calls saveProjectToDb() and deleteProjectFromDb() client-side from /admin.

Impact: Inconsistent architecture. If Supabase Row Level Security (RLS) is enabled without explicit public INSERT policies on sarang_reviews, reviews will fail silently and only save to local storage.

3.3 Admin Authentication Security Boundary

Files: src/app/admin/page.tsx & src/app/admin/login/page.tsx

Authentication for /admin is verified strictly via client-side sessionStorage.getItem('sarang_admin_auth').

Risk: There is no server-side Next.js middleware check (middleware.ts). If a visitor sets sessionStorage.setItem('sarang_admin_auth', 'true') in DevTools, they can view the admin interface.

Recommendation: Implement Next.js middleware.ts with encrypted HTTP-only session cookies or Supabase Auth SSR (@supabase/ssr).

4. Performance & UI Responsiveness

4.1 Viewport-Aware Scroll Heuristics

File: src/context/AgentChatContext.tsx

const isAlreadyVisible = rect.top >= 50 && rect.top <= 280;
if (!isAlreadyVisible) {
  targetEl.scrollIntoView({ behavior: 'smooth', block: 'start' });
}

The rect.top >= 50 && rect.top <= 280 heuristic effectively prevents screen jumps when the user interacts with specialist buttons inside Section 5 on standard 1080p/1440p displays. On compact laptops (e.g. 1366x768) or mobile landscape orientations, rect.top may sit slightly outside this range while the chat is still partially in view.

Refinement: Use dynamic viewport ratio calculation (rect.top < window.innerHeight * 0.4 && rect.bottom > window.innerHeight * 0.3).

4.2 Layout Density, Truncation & GPU Compositing

  • Specialist Cards: Uses grid grid-cols-2 gap-2 with line-clamp-1. On screens under 360px wide, long titles get truncated aggressively. Recommended: sm:grid-cols-2 grid-cols-1.
  • Double Transform Declarations: Both inline style={{ transform: 'translateZ(0)', isolation: 'isolate' }} and Tailwind classes transform-gpu isolate are declared simultaneously in Navbar.tsx and HeroSection.tsx.
  • GPU Composite Thread Load: Deep SVG filter blurs (blur-[160px]) across 7 sections can cause frame drops on older mobile GPUs.
